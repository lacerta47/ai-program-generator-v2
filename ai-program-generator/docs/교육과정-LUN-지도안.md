# LUN 교육과정 지도안

**대상** 초등 1~3학년(저학년) 중심 · 4학년까지 확장 가능
**차시** 총 12차시 (40분 기준) · 방과후·창의적 체험활동·돌봄교실
**구성** A트랙 `골라서 만들기` 6차시 → B트랙 `만들기` 6차시

> **설계 원칙** — 이 지도안은 **현재 구현된 기능만으로** 짰습니다. 아직 없는 기능(도전 미션, 칭찬 스탬프, 알림)은 쓰지 않습니다.

---

## 0. 왜 두 트랙으로 나누는가

| | 골라서 만들기 | 만들기 |
|---|---|---|
| 입력 방식 | **선택형** — 질문에 답만 하면 계획서 완성 | **서술형** — 아이가 직접 문장으로 씀 |
| 요구 능력 | 읽기 + 고르기 | 읽기 + **쓰기 + 분해하기** |
| 인지 부담 | 낮음 | 높음 |
| 배우는 것 | "프로그램은 **정해진 것들의 조합**이다" | "프로그램은 **내가 설계**하는 것이다" |

**순서를 뒤집지 마세요.** 저학년에게 빈 칸부터 주면 "뭘 써야 할지 모르겠어요"에서 멈춥니다. 선택형으로 *결과물이 나오는 경험*을 먼저 쌓아야, 서술형에서 "내가 쓴 문장이 프로그램이 된다"는 연결이 생깁니다.

두 트랙은 앱 안에서도 이어져 있습니다 — 골라서 만들기 결과 화면의 **`더 키우기`** 버튼을 누르면 그 계획서가 만들기 화면으로 그대로 넘어갑니다. 7차시에서 이 다리를 씁니다.

---

## 1. 전체 흐름과 도달점

| 단계 | 차시 | 핵심 질문 | 도달점 |
|---|---|---|---|
| **A-1 체험** | 1~2 | "내가 만든 게 진짜 움직이네?" | 완성작 1개, 실행 성공 |
| **A-2 관찰** | 3~4 | "이건 왜 이렇게 움직이지?" | 로직 카드를 읽고 설명 |
| **A-3 표현** | 5~6 | "내 작품을 친구에게 소개하기" | 게시판 업로드 + 핵심 한 줄 |
| **B-1 서술** | 7~8 | "내 말로 계획서를 쓰면?" | 4칸 계획서 직접 작성 |
| **B-2 분해** | 9~10 | "순서와 조건으로 쪼개기" | 동작 3칸(①②③) 채우기 |
| **B-3 개선** | 11~12 | "안 되면 어떻게 고치지?" | 고치기 2칸으로 디버깅 |

**평가 도구는 앱에 이미 있습니다** — 아이는 `마이페이지 → 개념 도감`, 교사는 `교사 콘솔 → 우리 반 학습 현황`(학생×5개념 격자)에서 확인합니다.

# A트랙 · 골라서 만들기 (1~6차시)

앱의 12가지 유형을 **난이도 순서로 재배열**해 배정합니다. 화면 배치 순서와 다릅니다 — 화면은 인기순, 여기는 **인지 부담순**입니다.

| 난이도 | 유형 | 왜 이 순서인가 |
|---|---|---|
| ★ 쉬움 | 소개·인사 카드 · 칭찬·운세 뽑기 · 룰렛·뽑기 | 결과가 즉시 눈에 보임, 규칙이 하나 |
| ★★ 보통 | 그림판 · 소리놀이 · 시계·타이머 · 꾸미기 놀이 | 조작이 여러 개, 상태가 변함 |
| ★★★ 어려움 | 퀴즈 · 숫자놀이·계산기 · 디지털 수족관 | 정답 판정·계산·자동 움직임 |
| ★★★★ 도전 | 게임 · 미로 찾기 | 규칙 여러 개가 동시에 |

---

## 1차시 — 처음 만나는 나의 프로그램

**학습목표** 선택형 질문에 답해 프로그램을 완성하고 실행해 본다.
**사용 기능** `골라서 만들기` → `소개·인사 카드`

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — "여러분이 오늘 진짜 프로그램을 만들 거예요" | 완성 예시 1개를 미리 띄워 두고 눌러보게 함 |
| 5분 | 접속·로그인 (학교·학번·PIN) | PIN을 칠판에 크게 적어 둠 |
| 20분 | **전개** — `소개·인사 카드` 선택 → 질문에 답 → 만들기 | 순회하며 **"고르는 데 정답은 없어요"** 반복 |
| 7분 | 완성작 실행·자랑 | 짝끼리 서로 화면 보여주기 |
| 3분 | **정리** — "무엇을 골랐더니 무엇이 나왔나요?" | 선택 → 결과의 연결만 짚음 |

### 지도 방법

- **이 차시에서는 코딩 용어를 쓰지 않습니다.** "프로그램", "만들기"까지만.
- 생성은 20~40초 걸립니다. 기다리는 동안 **로딩 화면의 로봇**을 보며 "지금 컴퓨터가 생각하는 중이야"라고 말해 주세요.
- **자주 나오는 상황**: 다 만들었는데 마음에 안 든다 → *다시 만들지 말고* 그대로 두게 합니다. 고치는 건 11차시에 배웁니다.

**관찰 포인트** 로그인에서 막히는 아이 / 선택을 못 하고 오래 망설이는 아이 → 다음 차시 짝 배치에 반영

---

## 2차시 — 다른 종류도 만들어 보기

**학습목표** 유형에 따라 질문과 결과가 달라짐을 안다.
**사용 기능** `골라서 만들기` → `칭찬·운세 뽑기` 또는 `룰렛·뽑기`

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — 1차시 작품 다시 열어 보기 | "지난번엔 카드였죠? 오늘은 뽑기예요" |
| 25분 | **전개** — 뽑기류 1개 만들기 | 질문이 1차시와 **다르다**는 걸 발견하게 함 |
| 7분 | 두 작품 나란히 비교 | "카드는 뭘 물어봤고, 뽑기는 뭘 물어봤죠?" |
| 3분 | **정리** — 유형별 질문의 차이 | 판서: 만들 것이 다르면 → **물어보는 것도 다르다** |

### 지도 방법

- **비교가 이 차시의 전부입니다.** 새 작품을 만드는 게 목적이 아니라, *질문이 다르다*를 알아채는 게 목적입니다.
- 빨리 끝낸 아이 → 같은 유형으로 **다른 답을 골라** 하나 더 만들게 합니다. "같은 뽑기인데 왜 다르지?"

---

## 3차시 — 이 프로그램은 이렇게 움직여요

**학습목표** 로직 카드를 읽고 프로그램의 동작을 순서대로 설명한다.
**사용 기능** `게시판` → 작품 선택 → **로직 카드**(①②③)

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — 내 작품을 게시판에서 열기 | (아직 안 올렸으면 교사가 예시 작품 지정) |
| 10분 | 로직 카드 ①②③ **소리 내어 읽기** | 한 명씩 한 줄씩 읽게 함 |
| 15분 | **전개** — 읽은 대로 **직접 눌러 확인** | "②번대로 진짜 되는지 해보자" |
| 7분 | 짝에게 내 작품 설명하기 | 로직 카드를 안 보고 말해 보기 |
| 3분 | **정리** — "프로그램은 **차례대로** 움직여요" | **순서** 개념 첫 등장 |

### 지도 방법

- 로직 카드는 저학년 어휘로 이미 쓰여 있습니다. **교사가 다시 풀어 설명하지 마세요.** 아이가 읽게 하는 것이 핵심입니다.
- 읽기가 어려운 아이 → 교사가 읽어 주되 **손으로 짚으며** 화면과 대조합니다.
- 로직 카드가 없는 옛 작품이 있을 수 있습니다. 그럴 땐 다른 작품으로 바꿔 주세요.

**연결** 이 차시에서 처음으로 `순서`라는 말을 씁니다. 이후 계속 씁니다.

## 4차시 — 개념 배지 찾기

**학습목표** 순서·조건·반복·입력·출력 5개 개념을 배지로 구분한다.
**사용 기능** `게시판` → **개념 배지** / **개념으로 찾기**(필터)

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — 배지 5개 소개 | 배지를 눌러 나오는 **쉬운 말 설명** 활용 |
| 10분 | 내 작품에 붙은 배지 확인 | "나는 몇 개 있어?" |
| 15분 | **전개** — 개념 필터로 **보물찾기** | "`반복` 배지가 있는 작품 3개 찾기" |
| 7분 | 찾은 작품에서 반복이 **어디에** 있는지 지목 | 화면을 짚게 함 |
| 3분 | **정리** — 5개 개념 이름 익히기 | 교실 벽에 배지 5장 게시 |

### 지도 방법

- 배지는 **코드를 실제로 분석해서** 붙습니다. AI가 임의로 붙인 게 아니라는 점이 이 활동의 신뢰 근거입니다.
- **순서·출력 배지는 거의 모든 작품에 있습니다**(흐리게 표시됨). "이건 기본이야, 다른 세 개가 진짜 보물"이라고 안내하세요.
- 보물찾기는 **검색창 + 개념 칩**을 함께 쓰게 합니다. 다음 차시의 게시판 활동으로 자연스럽게 이어집니다.

## 5차시 — 친구들에게 보여주기

**학습목표** 작품을 게시하고, 핵심을 한 줄로 표현한다.
**사용 기능** `게시판 올리기` — 별명 · 제목 · **내 작품의 핵심 한 줄**

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — "친구가 이걸 보면 뭘 알면 좋을까?" | |
| 8분 | 별명·제목 정하기 | **본명 금지** 안내(별명 규칙) |
| 12분 | **전개** — **핵심 한 줄** 쓰기 | 아래 발문 참고 |
| 10분 | 올리기 → 게시판에서 확인 | 처음 쓴 개념 **"처음!" 축하 배지** 확인 |
| 5분 | **정리** — 친구 작품 2개 보고 좋아요 | |

### 지도 방법 — 핵심 한 줄이 이 차시의 승부처

한 줄 쓰기는 저학년에게 어렵습니다. **"규칙"이 아니라 "목표"를 묻습니다.**

- ❌ "이 프로그램의 규칙을 쓰세요" → 아이가 멈춥니다
- ⭕ **"이걸로 뭘 하고 싶었어?"** → 말이 나옵니다
- ⭕ **"~해서 ~하는 게 목표예요"** 형태를 칠판에 제시

> 예시: *"사과를 먹고 뱀을 최대한 길게 키우는 게 목표예요"*

말로 먼저 시키고, 그 말을 그대로 받아 적게 하세요.

**주의** 핵심 한 줄은 **선택 항목**입니다. 끝내 못 쓰는 아이는 비워도 게시됩니다. 억지로 채우게 하지 마세요.

---

## 6차시 — 이어 만들기

**학습목표** 친구 작품을 이어받아 한 가지를 바꿔 본다.
**사용 기능** `게시판` → **이어 만들기(포크)** → 리믹스 배너

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — "친구 작품을 빌려서 바꿔볼 거예요" | 원작자 이름이 남는다는 점 강조 |
| 8분 | 친구 작품 고르기 | **좋아요가 적은 작품**도 고르도록 유도 |
| 20분 | **전개** — **딱 한 가지만** 바꾸기 | 화면 배너의 "한 가지씩 바꾸기" 문구 활용 |
| 5분 | 원작과 나란히 비교 | "무엇이 달라졌지?" |
| 2분 | **정리** — 원작자에게 고맙다고 말하기 | |

### 지도 방법

- **"한 가지만"이 규칙입니다.** 여러 개를 한꺼번에 바꾸면 무엇 때문에 달라졌는지 알 수 없습니다 — 이게 다음 트랙(디버깅)의 기초입니다.
- 포크 시 **원작자 크레딧이 자동으로 남습니다.** "훔치는 게 아니라 이어받는 것"이라고 분명히 말해 주세요.
- 자기 작품은 포크할 수 없습니다(버튼이 안 보임). 반드시 **친구 작품**을 고르게 됩니다.

# B트랙 · 만들기 (7~12차시)

여기서부터 아이가 **직접 문장을 씁니다.** 계획서는 4칸입니다.

| 칸 | 화면 문구 | 묻는 것 |
|---|---|---|
| 1 | 프로그램 이름 | 무엇을 만들까 |
| 2 | 어떻게 생겼나요? (색깔, 모양) | 보이는 것 |
| 3 | 어떻게 사용하나요? | 사람이 하는 것 |
| 4 | **동작** ①먼저 ②그다음 ③만약 ~하면 | 컴퓨터가 하는 것 |
| 5 | 더 바라는 점 | 추가 요청 (선택) |

**4번 동작 칸이 이 트랙의 핵심입니다.** ①② = 순서, ③ = 조건. 계획서 양식 자체가 컴퓨팅 사고를 유도하도록 설계돼 있습니다.

## 7차시 — 골라서 만든 걸 이어서

**학습목표** 선택형으로 만든 계획서를 서술형 화면에서 확인한다.
**사용 기능** `골라서 만들기` 결과 → **`더 키우기`** → 만들기 화면

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — "지금까지 고른 게 사실 '계획서'였어요" | |
| 10분 | 골라서 만들기로 1개 만들기 | 익숙한 유형으로 (부담 낮추기) |
| 10분 | **전개** — `더 키우기` 눌러 계획서 확인 | **내가 고른 게 글자로 들어가 있음**을 발견 |
| 10분 | 한 칸만 **손으로 고쳐** 다시 만들기 | "색깔만 바꿔 볼까?" |
| 5분 | **정리** — 두 방식의 차이 | 고르기 = 빠름 / 쓰기 = 내 마음대로 |

### 지도 방법

- **이 차시는 다리입니다.** 빈 화면에서 시작하지 않고, *이미 채워진 계획서*를 보여주는 것이 요점입니다.
- 재생성은 **다시 AI를 부릅니다**(사용량 차감). 반 인원과 한도를 미리 확인하세요 — 교사 콘솔 상단에 `우리 반 한도`가 표시됩니다.

---

## 8차시 — 내 말로 계획서 쓰기

**학습목표** 이름·모습·사용법을 직접 문장으로 쓴다.
**사용 기능** `만들기` — 예시 불러오기 + 1~3번 칸

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — **예시 이름 눌러 보기** | 칩을 누르면 계획서가 통째로 채워짐 |
| 8분 | 채워진 예시 **읽기** | "이렇게 쓰면 되는구나" |
| 15분 | **전개** — 예시 지우고 내 것 쓰기 (1~3번 칸) | 동작 칸은 **아직 비워 둠** |
| 7분 | 만들어 보기 | 동작을 안 써도 나오긴 함을 경험 |
| 5분 | **정리** — "뭔가 부족하지 않았어?" | 다음 차시 동기 유발 |

### 지도 방법

- **예시 불러오기를 반드시 먼저 씁니다.** 빈 칸을 응시하는 시간을 없애는 장치입니다.
- **동작 칸을 일부러 비웁니다.** 그러면 AI가 알아서 지어내고, 아이는 "내가 원한 게 아닌데?"를 경험합니다. 9차시가 그 답입니다.
- 맞춤법은 고치지 마세요. AI가 알아듣습니다.

---

## 9차시 — 순서로 쪼개기 (①②)

**학습목표** 동작을 '먼저 / 그다음'으로 나누어 쓴다.
**사용 기능** `만들기` — 동작 ① ②

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — **몸으로 순서 놀이** | "라면 끓이기를 순서대로 말해 보자" |
| 8분 | 화면의 ①② 칸 확인 | 힌트 문구 읽기 (예: 화면에 숫자 0이 보여요) |
| 15분 | **전개** — 8차시 작품에 ①② 채워 다시 만들기 | |
| 7분 | 전후 비교 | "안 썼을 때랑 뭐가 달라졌어?" |
| 5분 | **정리** — `순서` 배지 확인 | 3차시 개념과 연결 |

### 지도 방법

- **①은 "처음 화면"입니다.** 아이들이 가장 자주 틀리는 지점입니다. "프로그램을 켰을 때 **맨 처음 뭐가 보여?**"라고 물으세요.
- **②는 "누르면 뭐가 돼?"** 입니다. 화면 힌트(*버튼을 누를 때마다 숫자가 1씩 커져요*)를 그대로 읽어 주면 감을 잡습니다.
- 전후 비교가 이 차시의 증거입니다. **8차시 작품을 지우지 않게** 미리 안내하세요.

---

## 10차시 — 조건 넣기 (③)

**학습목표** '만약 ~하면 ~한다'를 문장으로 쓴다.
**사용 기능** `만들기` — 동작 ③

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — 조건 놀이 | "만약 비가 오면? / 만약 종이 치면?" |
| 8분 | 게시판에서 `조건` 배지 작품 관찰 | 4차시 필터 재사용 |
| 15분 | **전개** — 내 작품에 ③ 채우기 | "언제 끝나?" / "언제 축하해줘?" |
| 7분 | 만들어서 **조건이 실제로 걸리는지** 확인 | 일부러 그 상황을 만들어 보기 |
| 5분 | **정리** — `조건` 배지 획득 확인 | 개념 도감에서 확인 |

### 지도 방법

- **끝나는 조건**이 가장 쉽습니다. "숫자가 10이 되면 축하해요!" 같은 형태로 시작하세요.
- 조건을 쓴 아이는 개념 도감에 `조건` 배지가 새로 들어옵니다. **"처음!" 축하**가 뜨면 크게 인정해 주세요.
- 조건이 안 걸리는 경우가 생깁니다 → **11차시로 넘기세요.** 그게 다음 차시의 재료입니다.

---

## 11차시 — 안 되면 고치기

**학습목표** 기대와 실제의 차이를 말로 설명해 문제를 고친다.
**사용 기능** `고치기` — **어떻게 되길 원해?** / **지금은 어떻게 돼?**

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — "안 되는 건 실패가 아니에요" | 10차시에서 안 걸린 조건 꺼내기 |
| 10분 | 두 칸의 뜻 익히기 | **원하는 것** vs **지금 것** |
| 15분 | **전개** — 실제로 고치기 | 아래 발문 참고 |
| 7분 | 고쳐진 부분 확인 | "뭐가 달라졌어?" |
| 3분 | **정리** — 고치기도 만들기의 일부 | |

### 지도 방법 — 이 차시가 커리큘럼 전체의 정점

두 칸을 나눠 쓰는 것이 **디버깅의 본질**입니다. 프로그래머가 하는 일과 똑같습니다.

| 칸 | 발문 | 아이 답 예시 |
|---|---|---|
| 어떻게 되길 **원해**? | "네가 바라는 건 뭐야?" | *숫자가 10이 되면 축하가 나오면 좋겠어요* |
| 지금은 어떻게 **돼**? | "지금 눌러보면 뭐가 돼?" | *눌러도 점수가 그대로예요* |

- **"안 돼요"만 쓰면 안 고쳐집니다.** 이 말이 나오면 반드시 되물으세요: **"뭐가 어떻게 안 되는데?"**
- 두 번째 칸은 **선택**입니다. 하지만 저학년일수록 이 칸을 채우면 성공률이 확 올라갑니다.
- **첫 칸 힌트(연한 글씨)를 주목하세요.** AI가 그 작품에 맞는 *다음 도전*을 제안합니다. 아이가 막히면 그대로 써 보게 하세요.

---

## 12차시 — 나의 개념 도감

**학습목표** 자기가 모은 개념을 확인하고 다음 목표를 정한다.
**사용 기능** `마이페이지` → **개념 도감** → 개념별 내 작품

### 지도 순서

| 시간 | 활동 | 교사 |
|---|---|---|
| 5분 | **도입** — 도감 열기 | "5개 중 몇 개 모았어?" |
| 10분 | 개념 카드 눌러 **내 작품 확인** | 작품마다 *이 개념을 어떻게 썼는지* 표시됨 |
| 10분 | **전개** — 안 모은 개념 확인 | 흐린 카드 = 아직 안 쓴 개념 |
| 10분 | 그 개념을 쓰는 작품 1개 도전 | 시간이 모자라면 과제로 |
| 5분 | **정리** — 12차시 작품 전시 | 게시판에서 반 전체 훑어보기 |

### 지도 방법

- 도감은 **최근 작품 기준**으로 셉니다(많이 만든 아이는 '최근 작품 기준' 표시가 뜹니다).
- **개수 경쟁을 만들지 마세요.** 5개를 다 모은 아이보다, *안 모은 개념을 찾아낸 아이*를 칭찬하세요.
- 개념별 작품 목록에는 **"이 개념을 이 작품에서 이렇게 썼다"**는 설명이 함께 나옵니다. 발표 자료로 그대로 쓸 수 있습니다.

# 교사 운영 안내

## 수업 전 준비

| 시점 | 할 일 | 위치 |
|---|---|---|
| 학기 시작 전 | 학생 계정 일괄 발급 (학년·반·인원·공용 PIN) | 교사 콘솔 → 학생 만들기 |
| 〃 | **보호자 동의 확인** 체크 | 발급 화면 하단 |
| 〃 | 사용량 한도 설정 (1일형 / 총량형) | 학생 만들기 화면 |
| 1차시 전 | PIN을 칠판에 게시 | — |
| 5차시 전 | 관람 PIN 설정 (학부모 공유용) | 교사 콘솔 → 관람 PIN |

**한도 설정 요령** — 1차시당 아이 1명이 평균 **2~3회** 생성합니다. 12차시 × 3회 = **1인 36회**가 넉넉한 기준입니다. 총량형으로 잡으면 아낀 만큼 뒤에 몰아 쓸 수 있습니다.

## 수업 중 관찰과 평가

**교사 콘솔 → 우리 반 학습 현황**에 학생 × 5개념 격자가 나옵니다. 차시별로 이렇게 읽으세요.

| 차시 | 이 격자에서 봐야 할 것 |
|---|---|
| 4차시 이후 | 대부분 `순서`·`출력`만 있음 (정상) |
| 10차시 이후 | `조건`이 들어오기 시작 — **안 들어온 아이가 지원 대상** |
| 12차시 | `반복`·`입력`까지 3~4개면 충분히 성취 |

**평가는 개수가 아니라 변화입니다.** 9차시 대비 12차시에 개념이 늘었는지를 보세요.

## 안전 운영

- 학급 보드는 **그 반 학생과 교사만** 볼 수 있습니다. 공개 게시판과 분리돼 있습니다.
- 사진은 **학급 보드에서만** 올릴 수 있습니다. 공개 게시판에는 올라가지 않습니다.
- 부적절한 내용은 아이가 **신고**할 수 있고, 교사 콘솔 신고함으로 들어옵니다. 1차시에 신고 버튼 위치를 알려 주세요.
- 학부모 공유는 **관람 PIN**으로 합니다. 작품 1개만, 보기 전용으로 열립니다.

## 자주 생기는 상황

| 상황 | 대응 |
|---|---|
| 생성이 오래 걸림 | 20~40초는 정상. 로딩 화면을 보게 하세요 |
| "앗, 잘 움직이지 않아요" | AI가 만든 코드가 검증에 걸린 것. **다시 만들기**를 누르면 됩니다 |
| 다 만들었는데 마음에 안 듦 | 11차시 전에는 그냥 두게 하세요. 고치기는 배운 뒤에 |
| 아이가 로그인 못 함 | 학교 선택 → 학번 → PIN 순서 확인. 방화벽으로 막히는 학교가 있습니다 |
| 빨리 끝낸 아이 | 같은 유형 다른 선택으로 하나 더 / 친구 작품 이어 만들기 |

# 축약 운영안

전체 12차시가 어려운 경우입니다.

| 형태 | 차시 | 구성 |
|---|---|---|
| **체험형** (1회 특강) | 1차시 | 1차시 내용 + 게시판 구경 |
| **단기형** | 4차시 | 1 · 3 · 5 · 11차시 |
| **A트랙만** | 6차시 | 1~6차시 (1~2학년 권장) |
| **전체** | 12차시 | 1~12차시 (3학년 이상 권장) |

**어느 형태든 11차시(고치기)는 넣으세요.** "안 되면 고친다"가 이 도구로 배울 수 있는 가장 값진 태도입니다.
