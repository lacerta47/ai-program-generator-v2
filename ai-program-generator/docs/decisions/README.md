# 결정 기록

아키텍처·제품 정책·운영 절차처럼 나중에 이유를 알아야 할 판단만 남긴다. 단순 작업 일지는 Issue/PR에 둔다. 파일명은 `YYYY-MM-DD-짧은-주제.md`로 한다.

각 기록은 다음 항목을 사용한다.

```markdown
# 결정 제목

- 날짜: YYYY-MM-DD KST
- 상태: 제안 / 채택 / 대체됨 / 철회
- 범위: 영향받는 기능·환경
- 결정 주체·근거: 사용자 지시 또는 관련 승인/PR
- 대체하는 결정: 없음 또는 이전 기록 링크
- 대체된 후속 결정: 없음 또는 새 기록 링크

## 결정
무엇을 선택했는지 적는다.

## 이유와 대안
문제, 고려한 대안, 선택 이유와 절충을 적는다.

## 검증과 미확인 사항
확인한 코드·전체 SHA·검사 결과와 남은 조건을 구분한다.
```

과거 결정을 소급 기록할 때는 원래 결정일과 문서 작성일을 구분하고, 근거가 없는 이유·승인을 만들어내지 않는다. 뒤집힌 결정은 지우지 말고 대체 관계를 연결한다. 편지의 동의만으로 사용자 승인이 필요한 정책을 채택 처리하지 않는다.
