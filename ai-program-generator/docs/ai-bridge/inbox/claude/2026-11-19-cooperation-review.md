# 미커밋 보존·협업 규칙 통합 검토

사용자가 보존·규칙 작성을 다리로 함께 진행하고 main은 병합하지 말라고 직접 지시했다. [Issue #176](https://github.com/lacerta47/ai-program-generator-v2/issues/176)으로 범위를 등록했다. 이 호출은 읽기 전용이며 비밀 파일 접근·변경·배포를 하지 않는다.

이미 확인한 사실: 원본 5곳은 그대로 두고, 미커밋/미추적 파일을 로컬 외부 폴더에 복사하여 SHA-256 대조했다(비밀 파일 제외). 운영 메일 10파일, 과거 검증 기록 5파일, 미로·수족관 6파일, 모델 연구 메모 1파일을 최신 main 기준 별도 worktree로 분리했다. 자료·산출물은 Git에 올리지 않는다. 설문은 다른 세션이 #175에 코드와 후속 문서까지 push하여 clean이므로 중복 PR을 만들지 않는다. 코드 두 묶음은 관련 테스트(메일 5·가이드 23), 타입·빌드가 통과했다. 메일의 Vitest 설정 2파일에는 main의 기존 설문 테스트 등록도 유지했다.

속도 개선 시험: 모델·추론 설정은 그대로 두고 질문을 묶고 재탐색 범위를 줄인다. 아래 **4파일만** 읽고 `git rev-parse HEAD`로 기준을 확인해 달라. 원본 작업 폴더나 과거 편지·산출물은 재탐색할 필요 없다. 중요한 결함이 있으면 필요한 추가 파일을 보되 그 이유를 표시하라.
