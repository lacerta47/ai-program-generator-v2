# Claude·Codex 교대 연습 기록

이 문서는 [이슈 #189](https://github.com/lacerta47/ai-program-generator-v2/issues/189)의 사례와 인계 양식을 남긴다. 연습 시작 당시 main은 `13f6fd2b9cc536a4fe80c9cef537d4132b753b21`이었다. 프로젝트 규칙과 승인 범위는 [공통 지침](../../AGENTS.md)과 [협업 규칙](../COLLABORATION.md)을 따른다.

## 교대할 때 넘길 일곱 줄

```text
Issue / PR / 담당과 상태
작업 SHA(40자) / 먼저 볼 경로와 변경 범위
발신 측이 검증한 테스트 명령·환경·결과와 근거 위치
다른 AI가 직접 검토한 SHA와 파일 / 전달받은 증거
미확인 사항과 작업을 막는 조건
사용자 승인 출처·조건·사용/잔여 횟수(해당할 때)
다음 행동·담당과 기록 위치
```

수신자는 수락·부분 수락·보류 중 하나와 이유를 밝힌다. 이전 SHA에서 통과한 리뷰와 CI는 그 SHA에 귀속시킨다. 새 커밋은 변경 부분을 다시 확인한다. 조건으로 승인받은 작업은 새 커밋이 조건 안에 있는지 확인한 뒤 남은 승인 범위에서 이어간다. 일회성 사용 한도는 횟수를 뺀다. 운영 자동 배포가 발송·요금·데이터 변경으로 이어지는지도 따로 확인한다.

## 수정과 검증

- 발신 작업 폴더와 검토 작업 트리의 HEAD를 혼동하지 않도록 브리지 요청 문구를 정리했다.
- 미답 재질문을 가진 편지는 보관할 수 없고, 답신이 완료된 편지는 재질문을 추가해야 다시 호출할 수 있다. 같은 이름의 보관본이 있으면 두 파일을 유지하고 중단한다.
- Node 브리지 테스트 17건이 통과했다. 오프라인 실행 샘플로 미답 보관 거부, 답신 있는 편지 재호출 거부, 보관본 충돌 거부, 정상 보관과 링크 갱신을 확인했다. 틀린 검토 SHA와 등급은 모델 호출 전에 거부했다.
- 역방향에서 읽기 도구가 실패하면 필요한 근거를 확인한 SHA·경로·발췌로 넘겨 의견을 받는다. 해당 답신의 직접 검토는 미확인으로 남긴다.
