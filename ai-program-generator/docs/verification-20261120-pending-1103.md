## 1. 미리보기 빈 화면

두 미리보기 경로를 구분해 확인했다. 보안 헤더(`PREVIEW_SECURITY_HEADERS`)와 서빙 방식은 같고, 차이는 즉석 경로가 앱에서 `POST /api/preview`로 문서를 저장한 뒤 미리보기 도메인이 읽는다는 점뿐이다.

- **게시물 경로** `GET /api/preview/post/[id]`(비로그인): 공개 게시물 "나의 숲속 수족관" 정상 렌더링. iframe `https://ai-program-generator-v2-preview.vercel.app/...`, `sandbox="allow-scripts"`.
- **즉석 경로**(11-02에 빈 화면이 난 경로): 게시판 "이어서 만들기"(`/create?fork=`)는 AI 호출 없이 게시물 코드를 즉석 코드로 불러와 같은 경로를 탄다. `POST /api/preview` 200 → 교차 출처 iframe 765×327, `sandbox="allow-scripts"`, 수족관 렌더링·애니메이션 확인.
- 아래 2번의 **실제 수정 생성 결과**도 즉석 경로로 정상 렌더링.

판정: 현재 배포본에서 즉석 미리보기 빈 화면은 재현되지 않는다. 11-02의 빈 화면 원인은 **확정하지 못했다**. 당시 코드(ZIP)는 삭제돼 같은 코드로 재현할 수 없었다. 서버가 그때도 HTML 13,815자를 200으로 반환했으므로 문서 전달 문제는 아니며, 남는 후보는 (가) 그 생성물 자체의 렌더링 문제(캔버스 게임이 첫 입력 전 그리지 않거나 크기 계산 실패 등), (나) 당시 브라우저 환경(Chrome 확장·사용자 Chrome 프로필)이다. 플랫폼 경로 결함의 근거는 찾지 못했다. 재발 시 iframe 내부 콘솔과 생성 코드를 함께 보존할 것.

## 2. 운영 수정 생성 (유료 1회)

"이어서 만들기"로 불러온 수족관에 고치기 요청 "빨간 불가사리 친구도 연못 바닥에 하나 놓아 줘요" 실행.

- 약 45~75초 후 완료, "무엇이 바뀌었을까?" 성찰 안내 표시, 다음 도전 힌트 갱신.
- 결과: 연못 바닥에 빨간 불가사리 추가. 물고기·거북·수초·조작 버튼(밤으로 바꾸기, 소리, 친구 추가, 처음처럼)은 유지.
- 네트워크: `POST /api/generate` 200(브라우저 기록기에 `ERR_ABORTED` 표시), 이어서 `POST /api/preview` 200. 클라이언트(`lib/client/generate.ts`)는 스트림을 끝까지 읽고 `done`을 받은 뒤에만 결과를 반영하며 스스로 중단하지 않는다. 결과가 정상 반영됐으므로 결함으로 보지 않으나, 표시 원인은 추정(스트림 본문을 페이지가 직접 소비할 때의 기록기 표시)이다.
- 콘솔 오류는 로그인 팝업의 `Cross-Origin-Opener-Policy ... window.closed` 경고뿐(Firebase 인증 팝업, 기능 영향 없음).
- 결과는 게시하지 않았다.

## 3. 관리자 상세 화면 (읽기 전용)

| 화면 | 확인 |
|---|---|
| 신고 처리 | 로드, "처리할 신고가 없어요." |
| 가입자 | 50행 로드. 가입일 정렬 토글(2회 순서 변화), 작품 수 정렬 단조, "더 보기" 50→86행 후 버튼 사라짐, 정렬이 추가 행까지 유지(86행 단조). 검색 "test" 15행 모두 일치, 없는 값은 "결과가 없어요." |
| 전역 설정 | 일반 회원 기본 총 한도 입력(값 5)과 저장 버튼 표시. **저장 안 함** |
| 선생님 관리 | 발급 폼과 기존 교사 1명(사용량 표시) 로드. **발급 안 함** |
| 게시판 관리 | 트리 로드(공개게시판 18작품, 교육테스트 1,526작품 등) |
| 생성 예시 | 글 ID 지정 폼과 유형별 슬롯 목록 로드 |

관리자 화면은 같은 출처 iframe에도 열리지 않았다(클릭재킹 차단 헤더 정상 동작). 회원 이메일 등 개인정보는 이 기록에 남기지 않았다.
