# 생성 혼잡 대기·재시도

2026-11-02 검증 보강. 직접 만들기와 골라서 만들기의 생성·수정 호출에 공통으로 적용한다. 서버 영속 대기열이 아닌 브라우저의 제한된 자동 재시도다. 호출 모델과 운영 동시 상한(BizRouter 5+5, 직접 Gemini 4)은 변경하지 않는다.

## 동작

- 공유 슬롯 부족 또는 슬롯·학생 한도 예약의 확실히 커밋되지 않은 ABORTED 충돌로 AI 호출 전에 거절한 응답에만 HTTP 503, `code=generation_busy`, `retryable=true`, `Retry-After`를 반환한다. 접수 여부가 불명확한 다른 DB 오류는 자동 재시도 대상으로 삼지 않는다.
- 클라이언트는 이 명시적 응답에만 다시 입장한다. 서버 대기 시간과 점차 늘어나는 간격 중 큰 값을 사용하고, 최대 1초 미만의 무작위 지연을 더한다. 기본 간격은 3·6·12·20초이며 이후 20초를 유지한다. 서버가 더 긴 대기를 지시하면 그 값을 존중한다.
- 첫 혼잡 응답부터 120초를 기준으로 다음 입장 시도의 발송 기한을 제한하고, 최대 재시도 횟수는 10회다. 남은 기한 안에 다음 대기를 마칠 수 없으면 더 보내지 않고 종료한다. 이미 입장해 실행 중인 생성에 이 대기 기한을 적용하지 않는다.
- 대기에는 '여러 친구가 만들고 있어요. 잠시 뒤 다시 시도해요.'와 '기다리기 취소'를 표시한다. 생성 단계 칩과 체크리스트는 대기 중 숨긴다. 확정 대기 순번이나 가짜 생성 진행률은 표시하지 않는다.
- 취소·화면 이탈·로그인 사용자 변경 시 요청과 대기 타이머를 중단한다. 직접 만들기의 계획서·사진·예시를 대기 중 바꿔도 이전 요청을 취소한다. 입력·선택지·기존 작품·수정 입력은 대기 실패나 취소로 초기화하지 않는다.
- 동일 화면의 실행 중 재클릭은 AbortController 참조로 막는다. 재시도는 처음 직렬화한 본문을 재사용해 사진·유형·수정 내용이 바뀌지 않는다.
- 일반 401/403/429/503, 한도 소진, 공급사 오류, 통신 실패, 결과 검증 실패, 부분 출력 후 중단은 자동 재호출하지 않는다. 공급사가 이미 실행했을 가능성이 있는 요청을 자동으로 새로 생성하지 않는다.
- 골라서 만들기는 비동기 이름 검사 이전부터 중복 실행·취소를 관리한다. 검사 중 취소하면 화면은 즉시 복귀하며, 뒤늦게 검사가 끝나도 생성 요청을 시작하지 않는다.

## 한도 및 저장소

`genAdmission/{uid}`에는 `windowStart`, `count`를 저장해 슬롯 조회 전 UID별 분당 30회 입장 시도로 제한한다. 기존 `genRate/{uid}`의 생성 시작 제한(기본 10분 30회)은 슬롯·한도 예약 성공 후 실행 준비 시에 확인한다. 슬롯 부족·한도 예약 충돌·한도 소진으로 거절된 요청은 시작 횟수를 소비하지 않는다. 시작 빈도 제한 또는 확인 오류로 중단하면 이미 예약한 생성 한도를 환불하고 슬롯을 해제한다.

두 빈도 카운터 모두 취소·실패 환불 대상이 아니다. 실제 생성 한도의 기존 예약·실패 환불 처리는 유지한다. 입장 또는 시작 제한 저장소 오류는 생성 없이 중단하며, 확보한 슬롯은 해제한다.

완료 결과(done)를 전송한 뒤에는 성공으로 확정한다. 그 직후 연결이 취소되거나 공급사 정리 오류가 발생해도 성공을 실패로 바꾸거나 한도를 환불하지 않는다. 완료 전 실패·취소는 기존처럼 예약한 비용을 한 번 환불한다. 만료 카운터 청소는 트랜잭션으로 다시 만료 여부를 확인해, 다른 요청이 새 윈도로 갱신한 카운터를 삭제하지 않는다.

입장 카운터는 Firestore 클라이언트의 읽기·쓰기·삭제를 전면 차단한다. 기존 빈도 제한 유틸의 단일 `windowStart` 조건 정리를 사용하므로 복합 인덱스는 추가하지 않는다. 운영 반영 때 코드와 규칙을 함께 검토·배포해야 한다. 기본 거부 규칙도 유지한다.

## 검증

- 단위 223건 통과(기존 opt-in 2건 건너뜀). 모의 응답·가상 타이머로 동일 본문 재시도, Retry-After, 대기 기한, 취소·타이머 정리, 30명 독립 대기와 일부 취소, 오류 비재시도, 만료 카운터 정리 경합을 검증했다.
- API 57건 통과. 혼잡 미차감·계정 재검증·예약 중 취소·완료 직후 취소·사진 2회분 환불·시작 제한 실패 시 예약 환불을 검증했다.
- Firestore 에뮬레이터 53건 통과. 실제 생성 API·슬롯·시작 카운터·학생/교사 한도 트랜잭션을 연결했다. 같은 반 30명 및 교사를 분리한 30명이 대기 후 각각 30회만 생성·차감하고, 동일 학생의 동시 요청도 남은 한도 1회를 초과하지 않음을 확인했다. 모델 응답과 인증 검증만 모의 처리하며 실제 모델 HTTP는 차단했다. 운영 DB는 사용하지 않았다.
- 타입·린트·프로덕션 빌드 통과. 빌드에는 공개 Firebase 설정의 CI용 가상 값을 사용했다.
- 브라우저 점검은 실제 화면 컴포넌트와 모의 인증·입장 응답을 연결하는 로컬 전용 fixture를 사용한다. fixture는 output 아래에만 두며 배포 소스에 포함하지 않는다. 실제 AI·Firebase·게시판 쓰기를 호출하지 않는다.
- 중단 후 재개 점검도 완료했다. 직접 만들기 대기 중 계획서 변경 취소, 두 화면의 로그아웃·화면 이탈 취소, 골라서 만들기 수정 대기 취소와 기존 작품·수정 입력 보존을 확인했다. 취소 후 모의 입장 요청이 더 늘어나지 않았다. 추가 애플리케이션 소스 수정은 필요하지 않았다.

현재 단계는 영속 큐·학급별 공정 배정·공급사 장애 자동 전환·여러 탭 사이의 중복 작업 합치기를 구현하지 않는다. 실제 공급사 부하 시험은 별도 승인 후 진행한다.
