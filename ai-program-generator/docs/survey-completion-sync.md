# 내 정보 설문과 Google 제출 확인

## 동작

- 내 정보의 두 설문 버튼과 생성 완료 알림은 `/survey/create`, `/survey/easy`를 연다.
- 서버는 로그인한 계정의 만들기 방식마다 난수 코드를 한 번 발급하고 Google Forms의 참여 확인 코드 문항에 자동으로 채운다.
- 단순히 설문을 여는 동작은 완료로 처리하지 않는다. 내 정보로 돌아오거나 다시 설문을 열 때 Google 제출 기록을 조회한다.
- 일치하는 코드가 제출된 경우에만 완료 시각을 저장한다. 완료된 버튼을 누르면 이미 참여했다는 안내가 표시되고 설문 주소로 이동하지 않는다.
- 확인 서버 오류·잘못된 인증값·응답 형식 오류에는 재시도 안내를 표시한다. 브라우저가 임의로 완료 상태를 저장하는 API는 제공하지 않는다.
- 기존 안내 시각만 있는 계정도 참여 코드를 새로 발급받을 수 있다. 내 정보에서 먼저 연 경우에도 첫 생성의 안내는 유지한다.

## Google 설정

운영자 계정 `amh4753@gmail.com`에서 다음 Apps Script 프로젝트를 준비했다.

- [LUN 설문 제출 확인](https://script.google.com/home/projects/1X4rsI3bcKCS6BFXU54k7LrAH_-0U3nDoTvT54GQbsf9rLpKncd1PHbXF/edit)
- 소스는 `scripts/google-survey-sync.gs`이다. 두 양식의 코드 문항 번호는 `lib/feedback/generation.ts`와 함께 관리한다.
- 코드 문항은 기존 익명 링크의 참여를 막지 않도록 선택 문항이다. LUN에서 발급한 코드가 있는 제출만 계정에 연결된다.

설정 순서는 다음과 같다.

1. Google 권한 승인 후 프로젝트 설정의 스크립트 속성 `LUN_SURVEY_SYNC_SECRET`에 32자 이상의 임의 인증값을 직접 등록한다.
2. `checkSetup` 실행으로 두 양식의 코드 문항 조회와 `secretConfigured: true`를 확인한다. 인증값은 로그에 출력하지 않는다.
3. 배포 → 새 배포 → 웹 앱에서 실행 사용자는 소유자, 접근 대상은 모든 사용자로 설정한다. `doPost`는 인증값이 맞는 요청에만 제출 여부·시각을 반환한다. 답변 내용은 반환하지 않는다.
4. 웹 앱의 `/exec` 주소를 Vercel `GOOGLE_SURVEY_SYNC_URL`에 등록한다. 같은 인증값을 `GOOGLE_SURVEY_SYNC_SECRET`에 직접 등록한다. Preview·Production의 사용할 환경에 적용한다.
5. 환경설정이 적용된 새 앱 배포에서 내 정보 버튼 → 코드 자동 입력 → Google 제출 → 내 정보 복귀 → 완료 안내를 확인한다.

새 인증값 입력·저장은 사용자가 직접 수행한다. 값은 문서·Git·채팅에 남기지 않는다.

## 데이터와 검증 범위

`generationFeedback/{uid}`의 각 방식에 `offeredAt`, `code`, `codeCreatedAt`, `completedAt`을 보관한다. 기존 클라이언트 접근 거부 규칙과 계정 삭제 시 정리를 그대로 적용한다. 인덱스 추가는 필요하지 않다.

코드 없이 제출된 과거 응답은 계정별로 대조할 수 없다. 또한 이미 열린 Google 양식이나 직접 공유된 일반 링크의 제출까지 LUN 화면에서 차단할 수는 없다. LUN의 내 정보·완료 알림·직접 설문 경로에서는 제출 확인 후 재진입을 막는다.

로컬 검사에서 실제 제출 확인 모듈과 Apps Script 소스에 대해 올바른 코드·인증값만 완료 처리하는지 검사한다. 내 정보 카드와 설문 진입 페이지를 실제 컴포넌트로 렌더링해 미참여 열기, 자동 코드 입력, 완료 안내, 직접 주소 재진입 차단, 통신 오류 안내를 확인한다. 모의 제출 상태와 실제 Google 제출 확인 결과는 배포 점검에서 구분해 기록한다.

2026-11-19 로컬 검사에서 단위 229건·API 67건·Firestore 에뮬레이터 55건과 타입·린트·프로덕션 빌드를 통과했다. 기존 opt-in 단위 2건은 건너뛰었다.

Google 권한 승인과 두 코드 문항 조회, 인증값 설정 여부를 확인했고 웹 앱 버전 1을 배포했다. Vercel Production에는 연동 주소와 인증값을 등록했다. 웹 앱의 잘못된 인증값 요청은 HTTP 200의 `{ ok: false }`로 차단된다. 인증값 내용은 조회하거나 기록하지 않았다.

LUN 운영 반영 및 실제 계정의 제출 확인은 PR 배포 점검에 기록한다.
