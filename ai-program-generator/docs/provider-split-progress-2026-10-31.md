# 호출 분리 1차 구현 및 검증

2026-10-31. 대상: security-deps 작업 폴더. 운영 미배포, 미커밋. 1차 구현 이후 승인받은 실제 공급사 요청 10회 시험까지 완료했다.

## 계정 확인

로그인한 BizRouter 콘솔의 서비스 API 키 설정을 읽기 전용으로 확인했다. Gemini BYOK는 연동 안 됨으로 표시됐다. 서비스 키의 전체 모델 허용 상태를 확인했다. 개별 키의 예산·사용량·만료일은 공개 소스 기록에 포함하지 않는다. 키 원문을 열거나 설정을 수정하지 않았다.

크레딧/결제 화면에서 Tier 1, 분당 60회·동시 60회를 확인했다. 화면 설명은 이 한도가 API 키와 콘솔 계정 각각, 엔드포인트별로 적용되며 계약 한도는 다를 수 있다고 안내한다. 이는 Gemini 모델 제공사의 TPM·실시간 가용성까지 보증하는 수치가 아니다. BYOK 미연동 확인은 독립 공급 경로를 검토할 근거지만 무제한 또는 2배 처리 능력의 증거는 아니다. 확인 화면: https://bizrouter.ai/settings/credits 및 https://bizrouter.ai/settings/keys (로그인 필요).

## 구현

- opt-in 분산 모드 AI_PROVIDER=split 추가. 사용자 요청은 서버 요청 ID를 해시해 두 경로에 약 50:50 배정하며 기본·복잡 모델은 기존 Gemini 모델로 제한한다.
- 두 키가 없거나 모델 설정이 달라지면 분산 호출 준비를 거부한다.
- 사용자 생성 API에서 한도 예약 전에 경로별 공유 슬롯을 확보한다. 기본 최대 4개씩이며 환경설정으로 조정한다.
- Firestore 문서별 트랜잭션으로 슬롯을 확보하고 임대 갱신·취소·소유권 확인 해제를 구현했다. 단일 전역 카운터나 Vercel 메모리 큐를 사용하지 않는다.
- 슬롯 부족은 503과 재시도 간격 안내로 처리하며 생성 한도를 차감하지 않는다. 응답 중 다른 제공자로 전환하지 않는다.
- 새 슬롯 컬렉션은 클라이언트 전면 접근 금지 규칙을 추가했다. 문서 ID 직접 조회만 하므로 추가 질의 인덱스는 필요하지 않다.

## 검증

- 단위 검사 180건 통과, 기존 opt-in 시험 2건 건너뜀.
- API 검사 46건 통과.
- Firestore 에뮬레이터 검사 41건 통과. 실제 서버 SDK 트랜잭션으로 6개 병렬 요청 중 최대 2개 슬롯만 확보되는지 확인했고, 클라이언트 SDK로 슬롯 읽기·쓰기·삭제 차단을 검증했다.
- 타입 검사·린트·프로덕션 빌드 통과. 빌드는 공개 Firebase 변수에 CI용 가상 값을 사용했다.
- 실제 공급사 호출 10건을 경로별 2개, 합계 최대 4개 동시 실행했다. 10/10건 성공, 모든 HTTP 200, 추가 재시도 없음, 슬롯 잔여 0개였다. 이 시험은 슬롯 DB에 로컬 에뮬레이터를 사용했으며 실제 학생 계정·운영 DB 부하 검증은 아니다. 상세 결과는 `output/provider-split-smoke-20261031/report.md`에 기록했다.

## 다음 단계

1. 같은 실행 환경에 사용자 직접 입력으로 두 키 등록을 완료했고, 실제 설정으로 분산 사전 검사를 통과했다. 키 값은 출력하지 않았으며 사전 검사에서는 API를 호출하지 않았다. 현재 작업 폴더의 서비스 설정은 여전히 bizrouter 단독이다.
2. 사용자 승인 후 같은 Gemini 모델의 실제 요청 10회 시험을 완료했다. 직접 경로 5건과 BizRouter 5건 모두 성공했다. 기록/추정 합계 비용 약 648원(직접 약 319원 추정, BizRouter 약 328원 응답 기록)이며, 사진·인증된 학생 한도 검증은 후속 단계다. 운영 활성화 여부는 수업 규모 시험 후 판단한다.
3. 인증된 모의 학생 30명으로 단계 시험을 설계한다. 학생 한도·환불·DB 경합까지 포함해 요청 수·실행 환경·예산 승인 후 실행한다.
4. 대기시간과 실패율을 보고 60명 확대 및 영속 대기열 필요 여부를 결정한다. 자동 장애 전환과 중복 작업 합치기는 후속 검증 과제로 남긴다.
