# 생성 완료 후 설문 연결 점검

2026-11-19. 작업 브랜치 `codex/generation-feedback-survey`.

## 적용 내용

- 만들기와 골라서 만들기에 각각 별도 Google Forms 설문을 연결한다.
- 생성에 성공한 계정에만 안내하고, 한 계정에는 방식별 한 번씩 안내한다. 안내 후에는 닫거나 링크를 누르면 사라진다.
- Firestore 트랜잭션으로 같은 계정의 동시 요청을 처리하고, 계정별 안내 시각만 저장한다. 응답 제출 여부를 추적하지 않으므로 링크를 열어도 미제출할 수 있다.
- 로그아웃·계정 전환·경로 이동 때 진행 중인 확인 요청과 안내를 정리한다. 설문 API 오류·시간 초과는 생성 성공 알림으로 처리한다.
- 설문 답하기 링크는 새 탭으로 열며 `noopener noreferrer`를 적용한다. 안내 문구를 양식의 약 3분과 맞춘다.
- 안내 기록은 클라이언트의 직접 읽기·쓰기·삭제를 거부하고, 계정 삭제 시 서버에서 정리한다.
- 개인정보 안내에 선택적인 만 나이와 이용·학습 응답, Google Forms 수집 및 보고서 통계 활용을 명시한다.

- [만들기](https://docs.google.com/forms/d/e/1FAIpQLSc8jvYJ2f5X2Oyc7owB0Pvq5z3qcoi5BY89UR9DfkT7r-ZPug/viewform)
- [골라서 만들기](https://docs.google.com/forms/d/e/1FAIpQLSdElsfqP2kFm-NaUslZORw5Pc1Ww3d_1870NleY3KMOBVgaLA/viewform)

두 응답 화면의 제목, 10개 문항, 마지막 문항의 쉬운 표현과 제출 버튼을 확인했다. 점검 응답은 제출하지 않았다.

## 로컬 검증

- 단위 테스트 223건 통과, 기존 opt-in 2건 건너뜀.
- API 테스트 62건 통과. 계정·방식별 1회, 인증·정지 차단, 타 계정 UID 주입 방지, 잘못된 JSON과 DB 오류를 검사했다.
- Firestore 에뮬레이터 55건 통과. 실제 API 핸들러에 6개 요청을 동시에 보내도 각 방식의 안내가 한 번만 허용되고 두 기록이 함께 보존되는지 확인했다. 검사 데이터는 삭제했다.
- 타입 검사·린트·프로덕션 빌드 통과. 빌드에는 CI와 같은 공개 Firebase 가상 설정을 사용했다.
- 실제 provider와 toast를 사용하는 로컬 브라우저 시험에서 최초 안내, 동일 방식 중복 차단, 다른 계정의 안내, 계정 전환·로그아웃·화면 이동 정리, API 오류와 3초 시간 초과의 완료 알림을 확인했다. API와 인증은 모의 처리했다.
- 각 알림을 눌러 서로 다른 실제 설문이 새 탭으로 열리는지 확인했다. 360px 라이트·다크 화면에서 가로 넘침이 없고 링크 48px·닫기 44px의 터치 영역을 확인했다.
- 실제 유료 생성 호출은 실행하지 않았다.
