# 생성 품질 개선 전·후 200건 비교 평가

평가일: 2026-09-09
대상 커밋(개선 전 기준): `4be2453724dc041d785bb3a96fcb2b2cfeb2b739`
목적: 품질 점검 자료를 반영한 공통 프롬프트·유형 가이드·검증 규칙이 실제 생성 성공률을 높이는지 확인

## 결론

개선 방향은 유효했다. 동일한 기획 100개를 개선 전·후로 한 번씩 생성한 결과, 생성부터 자체 검증과 브라우저 조작 검사까지 모두 통과한 비율이 **77%에서 86%로 9%p 상승**했다. 실패 수는 23건에서 14건으로 39% 감소했다.

다만 동일 기획 쌍의 McNemar 정확 검정 결과는 `p=0.136`이다. 이번 100쌍만으로 5% 유의수준의 확정적 개선이라고 단정할 수는 없고, 개선 신호가 분명히 관찰된 단계로 해석해야 한다.

가장 효과가 컸던 유형은 음악으로, 엄격 성공률이 8/15(53.3%)에서 14/15(93.3%)로 상승했다. 반면 미로는 12/15(80.0%)에서 11/15(73.3%)로 소폭 하락해 후속 보완이 필요하다.

## 시험 설계

- 총 AI 생성 요청: 200건
- 고정 난수 시드로 만든 기획: 100개
- 각 기획을 개선 전과 개선 후 조건에서 각각 1회 생성
- 호출 순서 편향을 줄이기 위해 기획별 전·후 실행 순서를 교차
- 유형 배분: 그림판·미로·음악·수족관 각 15개, 나머지 8개 유형 각 5개
- 모델 실행: 현재 앱의 `paid` tier 호출 경로와 동일한 일반 생성 설정. 전용 `GEMINI_API_KEY_PAID`가 없어 앱과 동일하게 기존 공통 키로 폴백했으므로, 실제 결제 프로젝트 여부는 이 시험에서 확인하지 않았다.
- 게시·Firestore 저장 없음
- 외부 네트워크 차단, 실제 서비스와 같은 cross-origin sandbox iframe에서 실행
- 모든 반환 코드에 대해 초기 로드, 버튼·클릭 요소 최대 35개, 방향키·Space·Enter, 캔버스 드래그 검사
- 미로는 생성기 28개에 대해 20회씩 총 560회 시작점-출구 연결성 검사
- 평가 중 검증기가 결과를 버리지 않도록 생성 단계의 게이트만 우회하고, 개선 전·후 게이트를 사후에 각각 적용해 비교

이번 시험은 승인 예시(exemplar)와 사진 입력을 제외했다. 따라서 **공통 프롬프트·유형 가이드·검증 규칙 자체의 효과**를 비교한 것이며, 전체 운영 경로의 최종 품질을 그대로 재현한 시험은 아니다.

## 실제로 발견된 개선 후 문제

개선 후 실행 오류 9건 중 4건은 현재 게이트가 차단했고 5건은 놓쳤다.

- 차단 성공: 문법 오류 3건, 정의되지 않은 `updateMiniMap` 호출 1건
- 차단 실패: CSS 변수 문자열을 Canvas 색상으로 사용, 준비되지 않은 미로 배열 접근, `textContent`로 내부 SVG를 지운 뒤 다시 접근, AudioScheduledSourceNode 중복 시작, 0 크기 Canvas의 `getImageData` 간헐 오류
- 정상 실행 과잉 차단: 그림판 2건이 ASCII SVG를 base64 데이터 URL로 바꾸는 `btoa`를 사용했다. 한글 입력이 아니어서 실제 오류는 없었지만 일괄 금지 규칙에 걸렸다.

개선 전에는 저장소 접근, 미정의 함수·변수, 초기화 전 접근, 잘린 코드, 잘못된 DOM append, Canvas 0 크기 읽기, Web Audio 연결/해제 및 단위 오류 등이 관찰됐다. 특히 음악은 `createDelay(24000)`, non-finite 오디오 파라미터, 없는 gain/connect 대상 등 다양한 오류가 7/15에서 발생했다.

## 가이드 효과 평가

1. 공통 정확성 규칙은 효과가 있었다. 개선 후 게이트가 놓친 실행 오류가 17건에서 5건으로 줄었고, 미정의 이름·초기화 순서 계열 오류가 크게 감소했다.
2. 음악 가이드는 가장 효과적이었다. 사용자 조작 뒤 AudioContext와 노드를 준비하도록 한 규칙이 초기화·연결 오류를 크게 줄였다.
3. 그림판 가이드는 저장소 사용을 줄였지만 Canvas 크기 초기화와 SVG 버튼 갱신 순서까지는 막지 못했다.
4. 미로 생성 알고리즘 자체는 양호했다. 실행 가능한 생성기 28개에서 560/560 연결성 검사를 통과했다. 문제는 미니맵·렌더링·배열 초기화 같은 주변 기능에서 발생했다.
5. 새 게이트의 `btoa` 일괄 차단은 과도하다. 프롬프트에서 사용을 억제하는 것은 유지하되, 게이트는 직접적인 비ASCII 사용이나 위험 패턴만 판별하도록 좁히는 편이 낫다.

## 권장 후속 조치

우선순위 1은 게이트 정밀화다. `btoa` 전체 금지는 ASCII SVG 사용을 허용하도록 좁히고, `localStorage`도 무조건 차단과 안전한 try/catch 폴백을 구분할지 정책을 확정해야 한다.

우선순위 2는 이번에 나온 5개 미탐 패턴을 가이드와 검증에 반영하는 것이다.

- Canvas 크기가 0보다 큰 뒤 `getImageData` 호출
- `textContent` 변경 뒤 제거된 자식 SVG를 다시 조회하지 않기
- CanvasGradient에는 CSS `var(...)`가 아니라 `getComputedStyle`로 해석한 색상 전달
- AudioScheduledSourceNode는 한 번만 `start`; 재생마다 새 노드 생성
- 미로 배열 생성·렌더 완료 뒤 입력 처리, 부가 함수 호출 전 정의 확인

우선순위 3은 수정 후 동일 100개 기획을 다시 생성하는 확인 시험이다. 다음 라운드는 미로·그림판에 표본을 더 배정하고, 미로 자동 완주와 오디오 노드 상태 검사를 추가하는 것이 적합하다.
