# 생성 대기·재시도 심화 점검

2026-11-02. 사용자 요청에 따라 정상 흐름뿐 아니라 생성 호출·차감·환불 경계를 확대 검사했다. 이 변경의 커밋·푸시는 승인받았다. 운영 병합·배포 및 유료 생성은 이번 점검 범위가 아니다.

## 재현 후 수정한 문제

| 문제 | 보완 |
|---|---|
| 완료 결과 전송 직후 취소하면 성공 한도가 환불됨 | done 전송 후 완료 상태를 확정하고 늦은 취소·정리 오류가 환불이나 실패로 바꾸지 않음 |
| 비동기 이름 검사 중 화면 이탈 후 생성이 시작될 수 있음 | 검사 이전부터 취소·중복 실행을 관리하고, 검사 완료 뒤 취소 상태를 확인. 검사 중 취소에도 즉시 화면 복귀 |
| 같은 반 동시 요청이 공유 한도 문서에서 ABORTED 충돌로 실패함 | 확실히 미커밋인 충돌만 미차감 혼잡 응답으로 전환. 시작 카운터는 슬롯·한도 예약 성공 후 확인 |
| 만료 조회 직후 새 윈도로 갱신된 카운터가 청소 작업에 삭제될 수 있음 | 삭제 트랜잭션에서 최신 만료 시각을 다시 확인 |

DB ABORTED(10/ABORTED) 외의 접수 여부가 불명확한 오류는 자동 재시도하지 않는다. 한도 원자성이나 기존 권한 검사를 약화하지 않았다. 시작 빈도 제한을 통과하지 못하면 예약한 생성 한도를 반환하고 모델을 호출하지 않는다.

## 검사 범위와 결과

| 변수 | 확인 결과 |
|---|---|
| 일반 생성·수정의 혼잡 재시도 | 같은 본문·사진·유형 유지, 대기 후 성공 |
| Retry-After 초/날짜 및 반복 혼잡 | 지시 시간 준수, 간격 증가·무작위 지연, 120초/10회 한도 |
| 취소·이미 취소된 요청·입장 응답 대기 중 취소 | 추가 재시도 없음, 대기 타이머 정리 |
| 30명 브라우저 대기 중 5명 취소 | 25명만 한 번 재입장, 총 모의 입장 요청 55회 |
| 공급사 오류·통신 중단·부분 출력 후 실패 | 자동 재생성 없음 |
| 대기 뒤 계정 정지/토큰 만료 | 다음 요청의 인증 단계에서 차단, 차감·모델 호출 없음 |
| 한도 예약 중 요청 취소 | 모델 호출 전 중단, 정확히 한 번 환불·슬롯 해제 |
| 완료 결과 뒤 취소 또는 공급사 정리 오류 | 성공 유지, 한도 환불 없음 |
| 사진 생성 실패 | 예약한 학생·학급 비용 2회분을 한 번 환불 |
| 입장·시작 카운터 DB 오류 | 호출 중단, 필요한 예약 환불·슬롯 해제 |
| 같은 교사 소속 30명 동시 생성 요청 | 공유 문서 충돌은 안전하게 대기하고, 재입장 후 최종 생성·차감 합계 30회. 각 학생 시작 카운터 1회 |
| 교사별 한도를 분리한 30명 동시 요청 | BizRouter 10건·직접 Gemini 4건 입장, 나머지 16명 미차감 대기. 재입장 후 최종 생성·차감 30회 |
| 교사 공유 한도 3회, 학생 8명 동시 요청 | 최종 3회만 생성·차감하고 나머지 한도 차단 |
| 동일 학생의 동시 요청 5개, 남은 총 한도 1회 | 1회만 생성·차감, 나머지 한도 차단 |
| 실패·취소 후 학생/교사 사용량 | 예약·환불 대칭, 시작 횟수는 실제 실행 준비에 대해서만 보존 |
| 클라이언트의 카운터 조작 | 비로그인·일반 회원·학생·관리자 모두 직접 접근 거부 |
| 이름 검사 15초 지연 중 화면 이탈·취소 | 실제 화면 컴포넌트에서 모의 입장 요청 0회, 취소 즉시 입력 화면 복귀 |

최종 자동 검사: **단위 222건 통과·기존 opt-in 2건 건너뜀, API 57건 통과, Firestore 에뮬레이터 53건 통과**. 타입·린트·프로덕션 빌드와 diff 검사도 모두 통과했다. 빌드는 공개 Firebase 설정에 CI용 가상 값을 사용했다. 실제 화면의 지연된 이름 검사 취소·이탈도 확인한 최종 소스를 기준으로 검증했다.

## 증거와 실제 서비스 적용 한계

- API 연결 검사는 실제 Next.js 라우트와 로컬 Firestore 트랜잭션을 사용했다. 인증 검증과 모델 응답을 모의 처리하고 모델 HTTP를 차단했다. demo-lun-rules 데이터는 검사 후 정리했다.
- 같은 반 시나리오에서는 공유 교사 문서의 충돌이 발생할 수 있다. 이를 안전한 대기로 처리한 것이며, 한 반 30명이 실제 모델에서 동시에 성공한다는 처리량 보장은 아니다.
- 브라우저 검사는 실제 Creator·SurveyWizard와 모의 인증·이름 검사·모델 응답을 연결했다. 외부 인증·저장·격리 미리보기의 운영 통합 점검은 아니다.
- 실제 유료 모델 호출 및 운영 데이터 쓰기는 0건이다. Gemini/BizRouter의 실제 속도·429·TPM·원가·Vercel 시간 제한은 별도 승인된 시험이 필요하다.
- 여러 탭에서 보내는 서로 다른 HTTP 요청을 하나의 논리 작업으로 합치는 영속 중복 제거는 구현하지 않았다. 현재는 화면 내 중복 클릭 차단과 서버의 원자적 한도를 보장한다.
- 운영 동시 상한은 BizRouter 키별 5건·직접 Gemini 4건을 유지한다. 이 결과로 동시 상한을 추가 증설하지 않았다.
