# LUN 아키텍처 점검 — 문제점·개선점 (2026-09-03)

> `아키텍처-및-핵심알고리즘.md` 를 기준으로 코드 실물(rateLimit·posts·vercel.json·CI)을 대조해 정리. 심각도 순.

## A. 구조적 문제 (우선)
1. **자동화 테스트 부재** — 검증이 tsc+build+미커밋 selftest+수동. 순수 함수에 가까운 `studentQuota`·`validateCode`·`detectConcepts`·`moderation` 4개만이라도 vitest로 고정.
2. **게시판 검색이 클라 필터** — `fetchPosts` 20건 커서 + `filterPosts` 로 받은 것만 거름 → 게시물 수백 건이면 검색 누락. 제목 토큰 `array-contains` 또는 검색 시 끝까지 당기기.
3. **단일 세션이 협조적** — 리스너 기반이라 서버 강제 아님. `/api/generate` 에서 `sessions.activeToken` 대조하면 서버 강제.
4. **카운터 단일 문서 핫스팟** — 좋아요·조회·포크가 게시물 문서 직접 증가. 조회수만이라도 세션당 1회/디바운스로 완화.
